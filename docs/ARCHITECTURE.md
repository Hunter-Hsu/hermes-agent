# Architecture: hermes-agent

> Generated by `/map` on 2026-05-20. Covers commit `7c2ff742a`.

## Overview

Hermes Agent is a multi-modal AI agent runtime that connects large language models to users through interactive CLIs, messaging platforms (Telegram, Discord, Slack, WhatsApp, Signal, and 10+ others), and IDE integrations via the Agent Communication Protocol (ACP). It solves the problem of deploying a capable, tool-using AI agent across heterogeneous surfaces—chat apps, terminals, scheduled jobs, and remote editors—from a single codebase. The stack is primarily Python (backend runtime) with React/TypeScript (web dashboard and TUI), coordinated through FastAPI, SQLite, and a pluggable provider/plugin architecture.

## Directory Roles & Conventions

### `/agent`
**Role:** The core AI agent runtime — everything that happens between receiving user input and returning a response: conversation loop, context management, tool execution, model transport, memory, and skills.
**Convention:** Each LLM provider gets its own `*_adapter.py` file. Transport logic (format conversion) lives in `agent/transports/`, never in the adapter itself. New context engines must implement the `ContextEngine` abstract base. Do NOT put tool implementations here — those belong in `tools/`.

### `/tools`
**Role:** All tool implementations that the agent can call during a conversation. Each tool file self-registers via `registry.register()` at module import time.
**Convention:** Registration must happen at module level so the AST scanner in `registry.py` can discover it without executing imports. Runtime-installable dependencies must be declared through `lazy_deps.py`'s allowlist — arbitrary pip installs are blocked. Do NOT add business logic or LLM communication here.

### `/gateway`
**Role:** Long-running daemon process that bridges messaging platforms (Telegram, Discord, Slack, Matrix, etc.) to the agent runtime. One `GatewayRunner` instance manages all platforms; per-session `AIAgent` instances are cached via LRU (max 128, 1h idle TTL).
**Convention:** Each platform lives in `gateway/platforms/{platform_name}/`. All platforms must subclass `PlatformAdapter` from `gateway/platforms/base.py`. Message delivery (chunking to platform limits) is centralized in `gateway/delivery.py` — do not chunk inside platform adapters.

### `/hermes_cli`
**Role:** CLI entry point and user-facing tooling: setup wizard, credential management, skill browser, cron scheduler UI, and the dashboard server that backs the web UI.
**Convention:** `main.py:cmd_chat()` is the authoritative entry point for all interactive sessions. Profile selection (`--profile/-p`) must be parsed here before any other module imports.

### `/plugins`
**Role:** Optional extensions that ship as standalone pip packages. Covers additional LLM providers, memory backends, web search backends, image/video generation, observability, and additional messaging platforms.
**Convention:** Memory providers must be standalone pip packages — they are no longer accepted in-tree. Plugin activation is managed through the provider profile system, not direct imports. Each plugin subdirectory is independently installable.

### `/cron`
**Role:** Scheduled automation engine. A background thread ticks every 60 seconds, identifies due jobs, and runs them as non-interactive `AIAgent` instances with auto-approved tools.
**Convention:** Cron jobs write output to `~/.hermes/cron/outputs/{job_id}.log`. Prefixing a job's message with `[SILENT]` suppresses platform delivery while still logging locally. Job state (scheduling, next-run) is persisted in SQLite.

### `/acp_adapter`
**Role:** Exposes the Hermes Agent via the Agent Communication Protocol (ACP v0.9.0) for IDE and editor integrations (e.g., VS Code).
**Convention:** ACP is synchronous — the server uses `ThreadPoolExecutor` to wrap synchronous `AIAgent` calls. Session state, toolset expansion, and checkpoint/rollback all live in `acp_adapter/session.py`.

### `/skills`
**Role:** Bundled official skill definitions shipped as data files (Markdown + shell/API wrappers). Organized as `skills/CATEGORY/SKILL_NAME/SKILL.md`.
**Convention:** Skills are Markdown files, not importable Python. They are packaged via `setup.py` as data files. New in-tree skills go here; `optional-skills/` is for officially supported but non-default skills. Do NOT place Python tool implementations in `skills/`.

### `/providers`
**Role:** Declarative provider profile system. Profiles define which inference provider and model are active for a given context; the active profile is tracked in `~/.hermes/active_profile`.
**Convention:** Profile switching must go through this system — do not hardcode provider selection in agent or gateway code.

### `/ui-tui`
**Role:** Terminal UI powered by Ink (React for terminals) running as a Node.js child process. Handles live token streaming display.
**Convention:** TUI renders live tokens as they stream; the CLI REPL (`cli.py`) collects the full response. These are separate rendering paths — do not unify them.

### `/tui_gateway`
**Role:** Integration bridge between the messaging gateway daemon and the TUI rendering layer.

### `/tests`
**Role:** pytest test suite covering agent runtime, gateway, CLI, tools, and integrations.
**Convention:** Windows-specific tests (e.g., `gateway-windows`) must be tolerant of non-Windows environments via monkeypatching (e.g., `ctypes.windll`).

### `/web`
**Role:** React/TypeScript single-page application for the local dashboard, backed by a FastAPI server started by `hermes_cli`.

## Data Flow

### CLI Interactive Session

```
User input (terminal)
  └─> hermes_cli/main.py:cmd_chat()       # profile/credential check, env setup
        └─> cli.py:main()                  # load config.yaml + .env, create prompt_toolkit app
              └─> cli.py:_init_agent()     # instantiate AIAgent, init SessionDB
                    └─> agent/agent_init.py # provider detection, context-engine bootstrap
  
User message submitted
  └─> agent/conversation_loop.py:run_conversation()
        ├─ System prompt assembly
        │    ├─ Restore from SessionDB (prefix cache reuse) OR fresh build
        │    ├─ DEFAULT_AGENT_IDENTITY + SKILLS + MEMORY_GUIDANCE + context files
        │    └─ Memory context block (MEMORY.md, USER.md, recall results)
        ├─ agent/chat_completion_helpers.py:make_chat_completion()
        │    └─ Streaming request to LLM provider (with Anthropic prefix caching headers)
        ├─ Tool call validation + fuzzy-match repair (hallucinated names)
        ├─ Pre-execution guardrails (checkpoints for file writes + destructive commands)
        ├─ agent/tool_executor.py:execute_tool_calls_concurrent()
        │    └─ ThreadPoolExecutor (Ctrl+C propagation via _interrupt_requested flag)
        ├─ Tool results appended → compression check
        │    └─ context_compressor.py (if needed): summarize middle turns, new session ID
        └─ Loop back to model call OR return final response
  
  └─> Session persistence (SessionDB + JSON logs)
```

### Gateway Messaging Session

```
Platform webhook (e.g., Telegram message)
  └─> gateway/platforms/telegram/_on_message()
        └─> gateway/run.py:GatewayRunner.on_message()
              └─ LRU-cached AIAgent lookup (max 128, 1h idle TTL; create if missing)
                    └─> Same run_conversation() path as CLI
  └─> gateway/delivery.py:deliver_message()
        └─ Split response to platform chunk size → send to platform API
```

### Cron Scheduled Job

```
cron/scheduler.py:tick()  [every 60 seconds]
  └─> cron/jobs.get_due_jobs()
        └─> cron/scheduler.run_job()
              └─ Quiet-mode AIAgent (auto-accept all tools, no user prompts)
                    └─> run_conversation() path
              └─> gateway/delivery.py:deliver_message()
                    └─ Suppressed if message prefixed with [SILENT]
              └─> cron/jobs.advance_next_run()
              └─> Append to ~/.hermes/cron/outputs/{job_id}.log
```

### ACP (IDE Integration) Session

```
ACP client (e.g., VS Code extension)
  └─> acp_adapter/__main__.py (ACP server)
        └─> acp_adapter/server.py (ThreadPoolExecutor)
              └─> acp_adapter/session.py (session state, toolset, checkpoint/rollback)
                    └─> AIAgent.run_conversation() (synchronous call in thread)
```

## Gotchas

- **Exact dependency pinning is intentional, not an oversight.** All dependencies in `pyproject.toml` use `==X.Y.Z` pinning as a deliberate supply-chain hardening measure following the 2026-05-12 Mini Shai-Hulud worm incident (mistralai 2.4.6). New versions reach users only through explicit bumps and `uv lock` regeneration.

- **`run_agent.py` is a façade, not the real logic.** The `AIAgent` class there is thin — real initialization is in `agent/agent_init.py` (~1,400 lines) and the conversation driver is `agent/conversation_loop.py` (~3,900 lines). Debugging the agent loop means reading `conversation_loop.py`.

- **Context compression is destructive and irreversible.** When `ContextCompressor` fires, original conversation turns are replaced with a summary. A new session ID is created (linked via `parent_session_id`), so the original can be found in history but not resumed.

- **Tool registry uses AST scanning, not imports.** `tools/registry.py` discovers tool registrations by statically scanning Python AST, which breaks the circular import that would result from importing all tool modules at startup. Tools must call `registry.register()` at module level for discovery to work.

- **`model_tools.py` owns a single long-lived asyncio event loop.** It does not use `asyncio.run()` per call. This is intentional — reusing the loop prevents "Event loop is closed" errors when tool callbacks are invoked from worker threads.

- **Memory context from providers is non-authoritative.** Memory returned by external providers (Honcho, Mem0, etc.) is injected as "background reference." The system prompt memory block (MEMORY.md, USER.md) is authoritative. Conflicting values from the external provider should be treated as hints.

- **Lazy dependency installation is allowlist-gated.** `tools/lazy_deps.py` will only install packages on its explicit allowlist. Setting `security.allow_lazy_installs: false` in config disables all runtime installs entirely. This is a security control, not a convenience feature.

- **Anthropic adaptive thinking models (4.6+) reject `temperature`/`top_p`/`top_k`.** Passing these parameters causes a 400 error. The adapter must detect thinking models and strip these parameters before the request.

- **SQLite uses WAL mode with a fallback.** `state.db` operates in WAL mode for performance, but automatically falls back to journal mode on NFS/SMB/WSL1 mounts where WAL is unsupported. Code that assumes WAL-specific behavior (e.g., concurrent readers) will break on those filesystems.

- **Profile flag must be parsed before any module imports.** `--profile/-p` in `hermes_cli/main.py` sets the active provider profile. If module imports happen first, the wrong provider configuration loads. This is enforced by the argument parse order in `cmd_chat()`.

- **`hermes_state.py` uses `ContextVar` for home directory scoping.** This is how multi-tenant cron/gateway runs avoid contaminating each other's `~/.hermes` state. Code that resolves paths via `Path.home()` directly will break isolation.

- **Gateway agent cache is bounded.** `GatewayRunner` keeps at most 128 concurrent agent sessions in an LRU cache with 1h idle TTL. A user who returns after >1h gets a fresh agent with no in-memory conversation state (though session DB persists to disk).

- **Windows support is early beta; WSL2 is battle-tested.** Native Windows paths and subprocess handling have dedicated workarounds (e.g., `tzdata` package, hidden console windows). WSL2 is the recommended environment for Windows users.

- **Skills and Tools are architecturally distinct.** Skills are Markdown files with shell/API wrappers invoked via slash commands. Tools are Python modules registered in the tool registry and callable by the LLM during a turn. Conflating them leads to placing skill content in `tools/` or Python logic in `skills/`, both of which are wrong.

- **Reasoning tags are display-stripped but preserved.** `<think>`, `<REASONING_SCRATCHPAD>`, and similar tags are stripped from what the user sees, but saved verbatim in SessionDB. Querying the DB will show them; the rendered UI will not.
